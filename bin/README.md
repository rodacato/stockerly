# bin/

Two kinds of executable live here. Rails puts scripts that set up, check, deploy or run the app in
`bin/`, so the project's own scripts sit beside the generated binstubs.

## Written for Stockerly

| Script | What it does | Needs |
|---|---|---|
| `checks` | The ADR conventions a grep can see (boundaries, use cases, design tokens, number format). Runs in CI; the checks live in `script/checks/` | — |
| `quality` | RubyCritic (flog, reek, flay) over the Ruby files changed vs `origin/master`, or over the paths you pass | — |
| `setup-hooks` | Installs `pre-commit` into `.git/hooks`. `.devcontainer/post-create.sh` runs it | — |
| `pre-commit` | The hook itself: rejects a commit whose staged files match secret patterns (PEM key headers, GitHub and OpenAI tokens, hardcoded passwords and API keys), and runs `gitleaks` on the staged diff when it is installed | — |
| `prod-sync` | Mirrors the production database into `prodmirror_development`, so local work spends no API quota ([docs/ops/prod-mirror.md](../docs/ops/prod-mirror.md)) | SSH to `HOST_IP` for the dump half |
| `provision-server` | Prepares a fresh Ubuntu VPS for Kamal: Docker, cloudflared, a `deploy` user, UFW ([docs/ops/deploy.md](../docs/ops/deploy.md)) | root on the server |
| `board-check` | Reports drift between the GitHub Project board and the open issues ([docs/ops/github-workflow.md](../docs/ops/github-workflow.md)) | `gh` with `read:project` |

## Generated by Rails or a gem

Customised where the file says so, but not ours to design: `rails`, `rake`, `setup`, `dev`, `ci`
(steps in `config/ci.rb`), `jobs`, `thrust`, `docker-entrypoint`, and the gem binstubs `brakeman`,
`bundler-audit`, `importmap`, `kamal`, `rubocop`.

# Design decisions — open questions & findings (D1–Dn)

> **The registry the `.pen` files point at.** Briefs in `flows/*.pen` and warning notes in
> `ui-kit.lib.pen` cite these by number. Keep entries after resolution — record the outcome
> instead of deleting; the reasoning is the useful part.

**Status:** 37 entries · 32 resolved · 5 open · 1 🔴 high-impact · 13 🐞 app bugs (10 fixed, 3 open in slice 7)

**How entries work.** A `Dn` is a finding logged when a call isn't purely mechanical. In a
normal migration the design matches the code; here (a **redesign**) the design leads on visual
values, so entries also record forward design calls — each with what we picked and why.

| **D11** | The trade sheet on a real mobile browser | Bottom sheet as drawn · Full-screen form · **Sheet with a sticky footer** | ✅ **Route first, drawer as the presentation.** `/trades/new` is a real URL that renders a full page on its own; navigating to it from the Activos list loads it into a Turbo Frame with `data-turbo-action="advance"` and paints it inside a native `<dialog>` styled as the bottom sheet. | **D12** | The Consolidado's "¿Valió la pena?" comparisons | Drop them · Design + build now · **Design now, gate the engine** | ✅ **Design the full target; the engine is build-gated behind a 4-filter card, same treatment as D3.** The *data* is all there — `PortfolioSummary` (FX-historical cost basis), daily `portfolio_snapshots`, `PeriodReturnsCalculator`, allocation by type/sector, and **`BanxicoGateway` already fetches CETES auction rates** (`CETES_SERIES`, `fetch_auctions`), so the benchmark needs no new gateway. What is missing is the counterfactual calculation, and one thing more serious. 🔴 **`PeriodReturnsCalculator` measures money-weighted return** — it diffs the current total against an older snapshot ([`period_returns_calculator.rb:52-60`](../app/contexts/trading/domain/period_returns_calculator.rb#L52-L60)), so depositing cash and buying more makes the "return" rise while nothing performed better. Comparing *that* against CETES would state a falsehood on the one screen whose entire job is "did this beat doing nothing". **The comparison cards require time-weighted return (TWR); the existing period figures cannot be reused for them.** Snapshots carry `cash_value` and `invested_value`, so the flows needed to derive TWR are recoverable. Logged 2026-08-24. **Correction, 2026-08-24 (measured while reviewing the pending list):** the remedy stated above does not work. `portfolio_snapshots.cash_value` cannot carry the flows, because **nothing ever writes `buying_power`** — it is set to 0 at registration ([`create_portfolio_on_registration.rb:9`](../app/contexts/identity/handlers/create_portfolio_on_registration.rb#L9)) and never assigned again anywhere in `app/` or `lib/`; `ExecuteTrade` does not touch it. So `cash_value` is a constant and `invested_value` mixes market movement with contributions. **The flows are recoverable from `trades`, not from snapshots**: with no cash model, every buy is an external inflow and every sell an outflow, and `fx_rate_at_execution` already values them historically. See D27 for the bigger blocker underneath. **Engine built 2026-08-24 — `Trading::Domain::TimeWeightedReturn`.** Each day is its own sub-period, chained by multiplication, with that day's external flow removed from the day's snapshot. Flow valuation moved into `Trading::Domain::ExternalFlows`, shared with `day_gain`; the two entry points key on different columns deliberately (`since` on `created_at`, `by_date` on `executed_at`). A spec compares the two figures side by side on the case D12 described: a deposit makes the money-weighted number read >100% while TWR reports the honest 10%. `PeriodReturnsCalculator` stays as-is — as a display of what the balance did it was never wrong, only unfit for the comparison cards. **Still needed for the cards:** the CETES rate series (D28). |

The first threshold (1.0) read the artboard's own example (−3.0% index vs −2.1% asset) as *"aligned"* while the artboard calls it market-led, so it moved to 0.5. **Two smaller things the screenshots caught:** the accordion was offering `crypto_market` metrics on an equity, and rendering ~20 cards reading "—"; a metric with no value is now dropped, and an empty category with it — twenty empty cards is not depth. And `return` inside a partial **discards the buffer already written**, so the fundamentals empty state rendered nothing until it became a plain `if/else`. |

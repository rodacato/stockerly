Logged 2026-08-24. **Correction, 2026-08-24 (measured while reviewing the pending list):** the remedy stated above does not work. `portfolio_snapshots.cash_value` cannot carry the flows, because **nothing ever writes `buying_power`** — it is set to 0 at registration ([`create_portfolio_on_registration.rb:9`](../app/contexts/identity/handlers/create_portfolio_on_registration.rb#L9)) and never assigned again anywhere in `app/` or `lib/`; `ExecuteTrade` does not touch it. | **D19** | Alpaca as a market-data source | Skip · **Add for US prices + crypto** | ✅ **Add it, gated on its own 4-filter card — and pass `feed=sip` explicitly.** The detail that decides it: a free Alpaca account defaults to the **IEX** feed, which is roughly 2.5% of US volume, so an IEX-only daily close is *not* the official close and would misvalue positions. But [the FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) states that for historical queries the `end` parameter only has to be **at least 15 minutes old to query SIP without a subscription** — and a daily chart is always older than 15 minutes. So the consolidated close is free here, as long as the gateway asks for it instead of taking the default. Free plan: **200 requests/minute**, 7+ years of history, plus crypto (`/v1beta3`, BTC/USD, ETH/USD). **What it does not do:** fundamentals, BMV-listed equities, CETES — the MX side stays with Banxico and the current providers, so Alpaca complements and never replaces them. **Best candidate to replace: Polygon** for price history, whose free tier is 5 requests/minute (the Integraciones artboard shows it rate-limited for exactly that reason). **Boundary:** Alpaca is a broker; we consume its market-data API only. Trade execution stays out of scope ([[project-vision]] non-goals), and no API key with trading permissions belongs in this instance. Recommended 2026-08-24. **Amended 2026-08-26 — verified live against a Basic key. One premise is wrong, two limits are sharper than stated, and one capability was missed.** **(a) The IEX-default premise does not hold.** `feed` already defaults to `sip`: the same query with and without the parameter returned byte-identical payloads (2,103 bytes), and the reference states *"SIP requires real-time subscription; otherwise defaults to 15-minute delayed data"*. What a Basic key loses is **recency, not venue**. Sending `feed=sip` explicitly stays correct — defaults move and it costs nothing — but it is no longer what decides this entry. The venue gap is real where it applies: `feed=iex` returns **3% of the volume** (AAPL 2026-08-17: 1,160,745 shares against 38,414,225) in an **identical response shape with no field naming the feed**, so a degraded series is indistinguishable from a good one except by magnitude. **(b) Alpaca cannot serve a current price at all.** `/v2/stocks/{sym}/bars/latest`, `/v2/stocks/snapshots` and any bars window inside 15 minutes all return `403 {"message":"subscription does not permit querying recent SIP data"}`. It therefore does **not** replace Polygon on the live-quote path, only on **confirmed EOD history**; the current-quote role moves to Finnhub, whose `/quote` is free at 3,600 calls a day. **(c) No indices.** `SPX` returns `{"bars":{}}` with HTTP **200** — as does any unknown symbol, `WALMEX` included — so absence looks like success. `fetch_index_quotes` has no Alpaca replacement, and neither Massive's free tier nor DataBursatil's frozen index feed provides one. **(d) No earnings**, documented and confirmed. This bites [[D31]]: of the three Descubrir blocks routed here, *Olas* and *Titulares* hold, **Reportes must come from Finnhub**. **(e) Missed capability:** `/v1/corporate-actions` returns cash dividends and splits free on Basic with `ex_date`, `payable_date`, `record_date` and `rate` — more fields than FMP, whose `/api/v3` 403s for accounts created after 2025-08-31. Evidence: `redesign/probes/probe.rb alpaca`, 2026-08-26. |

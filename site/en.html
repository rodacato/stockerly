Your invested net worth, on one screen.

Stockerly tracks what you own — US stocks, crypto and Mexican CETES — and reports all of it in pesos using the exchange rate from the day of each trade, not today's. You run it on your own server. There is one account: yours.

Run it locallyRuby + Postgres
$ git clone https://github.com/rodacato/stockerly.git
$ cd stockerly
$ bin/setup

Who this isn't for

Self-hosted means you are about to spend an evening on this. These are not limitations waiting to be fixed — they are decisions, each one recorded in the repo.

More than one person
Single-user by design. One instance, one account, no roles, no sharing, no multi-tenancy. A household needs two instances.
Investors outside Mexico
The math assumes MXN and USD through a Mexican broker: CETES, Banxico's FX fix, the BMV. It is not a generic international tracker.
Anyone wanting broker sync
No Plaid, no Yodlee, no SnapTrade, ever at this scale. You type trades or import a CSV. Aggregator fees helped kill a same-stack competitor.
Day traders
Daily close, not ticks. No sub-daily resolution, no streaming quotes.
Tax preparation
No ISR reports, no SAT integration, no lot tracking, no withholding math. It tracks patrimony; it does not replace your accountant.
Anyone who needs support
No SLA, no support guarantee, no advance notice of breaking changes. It is one person's daily driver that happens to be readable and runnable.

A tracker built around one question

Am I up or down, in the currency I actually spend? Everything else on the screen exists to explain that number or to keep it honest.

Multi-currency that tells the truth

Cost basis is FX-weighted. The unrealised gain is split into what the asset did and what the peso did — for a Mexican investor holding US stocks those are two different stories, and most trackers report only the first.

Three tiers, not one list

Holdings is what you own, Watchlist is what you follow, and Tracked is the catalogue the sync jobs read. A symbol can be in the catalogue without pretending you bought it.

CETES as a first-class asset

Mexican fixed income sits beside the equities, with maturity lead time, and the portfolio's return is measured against reinvested CETES — the benchmark a Mexican investor actually gives something up for.

Descriptive, never prescriptive

It says "AAPL entered oversold per RSI(14)". It does not say buy, sell, or now is a good time. Indicators and composite scores are in; predictions and recommendations are out, on purpose.

Installable, and it works offline

It ships as a PWA: install it to a phone home screen, get push notifications when a rule fires, and keep reading the last figures it loaded when the network is gone.

What it costs you to run

Not money — it is MIT. Attention, and a short list of things that have to be true on your server.

8
market-data providers, every one of them optional. It runs with none configured; you just get no live prices.
6
bounded contexts. Writes cross them as domain events, reads through a published API, and an ADR names every seam.
4
PostgreSQL databases — primary, cache, queue, cable. No Redis to run, no Node to build.
1
account on the instance, created by the Setup Wizard on first boot. There is no second one to make.
0
accounts with anyone else, including me. No aggregator, no telemetry, no external error service.

One command, on your machine

bin/setup is idempotent: it installs gems, creates and migrates the four PostgreSQL databases, seeds them on first creation, and starts the server. No market-data API key is needed to run.

Dev container

Open the folder in VS Code or Codespaces and choose Reopen in Container. Setup runs itself; then bin/dev.

Bare metal

Ruby 4.0.6 and a PostgreSQL 16 on localhost. Node.js is not required — JavaScript ships through import maps and CSS through the Tailwind standalone compiler.

Both paths end hereport 4100
$ bin/setup                  # gems, databases, seeds, server
$ bin/jobs                   # second terminal: alerts, syncs, notifications

  open http://localhost:4100
What the first screen actually is. The development seeds create four demo users, so bin/setup lands you on the login — sign in with demo@stockerly.com / password123. The Setup Wizard that creates the single real account only appears on an empty database, which is what a genuine first boot looks like. GETTING_STARTED.md has the one-liner to get there.

For production, Stockerly deploys to any Linux server with Kamal 2 and Docker. The reference deployment uses a VPS behind a Cloudflare Tunnel, so no inbound ports are opened — but nothing in the app depends on the maintainer's infrastructure. See docs/ops/deploy.md.
